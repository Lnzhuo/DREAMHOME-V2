# DREAMHOME V2 产品与实现

DREAMHOME 面向希望自己布置住宅的人。用户可以先画准一间屋，也可以从普通平层户型出发，摆放真实家具，再带着同一份设计在平面和三维之间来回修改。打开「晴木之家」可直接编辑一套三室两厅两卫住宅。

## 从首页到设计文件

| 用户要做的事 | 产品入口 | 对应实现 |
| --- | --- | --- |
| 从空房量尺寸 | 首页 13 类房间，右侧「空间参数」 | 可改轮廓、长宽、层高、墙厚、踢脚线和门窗 |
| 配整套住宅 | 首页平层户型，包括两室转角客餐厅和三室双阳台，左侧空间树 | 每层共墙、门洞和房间轮廓共享几何，修改邻接关系会重算共墙并校验通路 |
| 摆家具 | 左侧「家具」和「Lux3D 原创」 | 卡片搜中文名称或类别，预览真实 GLB，放入当前房间或拖到地面 |
| 换材料 | 「材料」和右侧「墙地配色」 | 墙、地或单件家具可设独立材料，8 套配色调用目录里的纹理 |
| 上传自己的资料 | 家具库「导入与生成家具」、平面图参考底图、AI 图片附件 | 上传 GLB 后可设尺寸，户型图按实际宽度校准，图片可交给视觉模型辅助修改 |
| 检查空间 | 2D 平面、3D 编辑、全景、剖视、第一人称漫游 | 房间和家具用米，在同一份设计上编辑，楼梯连接楼层 |
| 保存或分享 | 自动保存、「保存项目」、「设计文件」 | 本机 IndexedDB、多项目和版本快照、可携带自有 GLB 和参考图的 .dreamhome |
| 获取 AI 方案 | 右侧「AI 设计助手」与顶栏「API 管理」 | 服务端读取房间、选中家具和真实资产候选，模型返回可预览、应用和撤销的结构化命令 |

## 实现边界和数据

沿用 Phase 3/4 的 Three.js 场景、TransformControls、资源与项目仓库。SceneDocument 是可保存的设计，关系为建筑、楼层、房间、共墙与开口。AssetDefinition 保存模型与来源，Placement 保存模型在空间中的摆放和外观。两个相同模型实例可以具有不同的位置、旋转、缩放与材料。房间净面积、家具包围盒和楼层标高均按米计算。

`src/data/v2-contracts.js` 定义模板，`src/ui/rooms` 编辑建筑关系；`src/game/Game.js` 和平面编辑器从同一文档渲染。住宅模板的房间和窗户是可编辑的示意布局。实景参考图在界面列出作者和许可，摆放尺寸来自设计参考或用户测量。导入实拍照片会保留原图，可以给视觉模型作参考，要生成单件家具则走独立的 Lux3D 任务。

`data/library/index.json` 为已归档的模型和材料目录。Lux3D 真实任务和 SHA 对应本地 GLB，Poly Haven 与 Kenney 的资产按来源标记。新模型按真实包围盒校准设计参考尺寸，缩略图由归档模型渲染。解析、场景回归、视觉质量和许可证分别登记在资源元数据。

`server/security` 管理平台与用户凭据，`server/ai` 接入 OpenAI 兼容服务，`server/lux3d` 负责生成和预算约束。生成任务在浏览器关闭后仍由后台回收。代码、个人凭据、项目设计文件与账户账本各有存储位置。启动器只绑定本机回环地址。

## 工程入口

| 入口 | 用途 |
| --- | --- |
| `启动DREAMHOME.cmd` | 启动本地 Windows 发行版 |
| `npm ci`、`npm run dev` | 从源码安装并启动开发服务 |
| `npm test`、`npm run build` | 单元和契约回归、生产静态构建 |
| `node scripts/release/verify-v2.mjs` | 从真实浏览器执行核心编辑流程 |
| `node scripts/release/verify-residence.mjs` | 已布置平层、跨会话导入、窄屏编辑验证 |
| `docs/ASSET_LIBRARY_SPEC.md`、`docs/ROOM_TEMPLATE_CATALOG.md` | 资产、材料、空间模板和来源 |
| `docs/BYOK_SECURITY_SPEC.md`、`docs/LUX3D_CREDIT_LEDGER.csv` | API 配置、生成任务和积分明细 |
